# CLAUDE.md — Проект «Спортивные судьи»

## Что это за проект

Flask веб-приложение для ведения базы данных спортивных судей по спортивному туризму (Московская область). Для каждого судьи ведётся электронная карточка учёта судейской деятельности: личные данные, история присвоения квалификационных категорий, прохождение теоретической подготовки и сдача квалификационного зачёта, практика судейства официальных соревнований. По данным карточки формируется официальный документ Word — «Карточка учёта судейской деятельности спортивного судьи» — в точном соответствии с образцом из `data/`.

## Модели базы данных

### Subject (субъект Российской Федерации) и LocalBranch (местное отделение)

Переключатели в шапке — замена пункта «Судьи» на «Судьи ЦФО» + выпадающий список субъектов РФ (первый дропдаун), и отдельный пункт «Региональная федерация» с выпадающим списком местных отделений (муниципальных образований), вложенных в выбранный субъект (второй дропдаун). В отличие от аналогичной пары Subject/Organization в REGTEAM_RAFTING, здесь это НЕОБЯЗАТЕЛЬНЫЙ фильтр, а не обязательная область видимости всего приложения: пока субъект не выбран, в шапке — «Судьи ЦФО», список судей не фильтруется (видны судьи всех субъектов). Judge.region / Judge.municipality остаются свободнотекстовыми полями, как и были — справочники лишь дают готовые пункты меню, фильтрация (`routes/judges.py`, `_scope_to_subject_and_branch()`) идёт по точному совпадению с их значением по имени.

В шапке — только переключение (switch/clear). Добавление, переименование и удаление — на странице «Настройки» (`templates/settings.html`, раздел «Субъекты ЦФО и местные отделения»): у каждого субъекта своя карточка с формой переименования + своей организации, осуществляющей учёт судейской деятельности (наименование/адрес/контакты — раньше были в Settings как одна общая запись, теперь свои у каждого субъекта), кнопкой удаления (каскадно удаляет и его местные отделения) и вложенным списком местных отделений с такими же формами; добавление нового местного отделения — через `subject_id` в скрытом поле формы (не через сессионный «текущий субъект», страница настроек не зависит от выбора в шапке).

| Модель | Поле | Тип | Описание |
|---|---|---|---|
| Subject | id | Integer PK | |
| Subject | name | String | Наименование субъекта РФ (уникальное). При первом запуске сидируется списком `subjects.ЦФО_СУБЪЕКТЫ` (`обеспечить_субъекты_цфо()`) — Белгородская область, Город Москва, Липецкая область, Московская область, Рязанская область |
| Subject | organization_name | String | Наименование организации, осуществляющей учёт судейской деятельности в этом субъекте |
| Subject | organization_address | String | Адрес (место нахождения) организации |
| Subject | organization_contacts | String | Телефон, адрес электронной почты организации |
| Subject | organization_leader_position / organization_leader_name | String | Должность и «И. О. Фамилия» руководителя организации — подпись в представлении |
| LocalBranch | id | Integer PK | |
| LocalBranch | subject_id | FK → Subject | удаляется каскадно вместе с субъектом |
| LocalBranch | name | String | Наименование муниципального образования (уникальное в рамках субъекта) |

`judge_docx_generator.generate_judge_card(judge, settings, subject)` — организация в шапке карточки судьи подставляется из `Subject`, подобранного в `routes/judges.py` (`judges_export`) по точному совпадению `Subject.name == judge.region`, а не из общих `Settings` (там остался только вид спорта — см. ниже).

Выбор (для фильтра списка судей) хранится в сессии (`subjects.py`: `текущий_субъект_id()` / `текущее_местное_отделение_id()`), выбор субъекта сбрасывает выбранное местное отделение. Маршруты в `app.py`: `GET /subjects/<id>/switch`, `GET /subjects/clear`, `GET /local-branches/<id>/switch`, `GET /local-branches/clear` — используются только из шапки; `POST /subjects`, `POST /subjects/<id>/edit`, `POST /subjects/<id>/delete` и аналогично `/local-branches/...` (добавление принимает `subject_id` явным полем формы) — используются только со страницы «Настройки».

Первая версия сидировала все 18 субъектов ЦФО — список сокращён до 5 основных одноразовой миграцией `subjects.убрать_лишние_субъекты_цфо()`, отмеченной флагом в таблице `SchemaFlag` (`models.py`), чтобы не стирать субъект, который пользователь позже сам добавит заново под тем же названием.

Текущая квалификационная категория судьи (`current_category`) — не хранимое поле, а свойство: категория из самой последней по дате записи `JudgeCategoryRecord`. Именно по ней работают фильтры ССВК/СС1К/СС2К/СС3К на странице списка судей.

### JudgeCategoryRecord (история квалификационных категорий, 1 запись = 1 строка карточки)

category, action («присвоена»/«подтверждена»/«лишена»/«восстановлена»), date, document_number, issuing_organization, signed_by, record_keeper.

### JudgeTrainingRecord (прохождение теоретической подготовки, сдача квалификационного зачёта)

seminar_name, seminar_date, organizer, location, participant_category/score (в качестве участника), lecturer_category/score (в качестве лектора), exam_protocol_number, exam_score, record_date, record_keeper.

Внимание к датам (исторически так раскладывает импорт 13-колоночного образца карточки): `participant_date` фактически хранит **дату занятий в качестве лектора** (колонка «Дата» под группой «Лектор»; в формах — «Дата (лектор)», в выгружаемой карточке столбец удаляется), а `lecturer_date` — **дату сдачи квалификационного зачёта** (в формах — «Дата (зачёт)»).

Даты семинаров хранятся строкой (в образцах встречаются диапазоны вида «09-10.11.2019г.»), не `Date`.

### JudgeCompetitionRecord (практика судейства официальных спортивных соревнований)

event_date, location, judge_position, competition_name, competition_status, score, in_nomination, record_date, record_keeper. № в ЕКП / КП пишется прямо в `competition_name` (напр. «…, КП № 1378-СМ»), баллы — в `score` («Отлично, 12 баллов»); бывшие отдельные колонки `ekp_number`/`points` одноразово перенесены туда (`app._перенести_екп_и_баллы`) и не используются.

`in_nomination` — галочка «В представление» (третий пункт в ячейке «Действия» таблицы практики судейства) (сохраняется сразу по клику, `POST /judges/competition-records/<id>/nomination`). `None` — галочку не трогали: тогда соревнование включено, если проведено не раньше `Judge.previous_category_date` (свойство `included_in_nomination`).

`competition_name` (полное наименование соревнования с видом программы) и `competition_status` (официальный статус: «Чемпионат субъекта Российской Федерации», «Первенство России» и т.п.) — два разных поля, в документе выводятся двумя отдельными строками одной ячейки.

## Маршруты (routes/judges.py)

- `GET /judges/` → список активных судей + кнопки-фильтры ССВК/СС1К/СС2К/СС3К
- `GET /judges/vsk`, `/1k`, `/2k`, `/3k` → судьи данной категории (по `current_category`), включая исключённых — активные подсвечены
- Все страницы списка дополнительно сужаются выбранными в шапке субъектом РФ / местным отделением (`_scope_to_subject_and_branch()`, см. Subject/LocalBranch выше)
- `GET /judges/preview?subject_id=<id>` / `?branch_id=<id>` → JSON (count + до 8 активных судей: ФИО, дата рождения, категория) для всплывающей таблицы-превью при наведении на пункт субъекта/местного отделения в шапке (`static/js/main.js`, `data-preview-url` в `templates/base.html`) — клик по пункту, как и раньше, просто ведёт на отфильтрованный `/judges/`
- `GET|POST /judges/new`, `GET /judges/<id>`, `GET|POST /judges/<id>/edit`
- `POST /judges/<id>/activate|deactivate|delete` (`delete` также сразу удаляет судью на RAFTING_CFO — см. ниже)
- `POST /judges/<id>/send-to-site`, `POST /judges/send-all-to-site` — отправка на RAFTING_CFO (кнопки «Отправить на сайт» / «Отправить всех на сайт»)
- `GET /judges/<id>/export` → генерация и скачивание карточки судьи в формате .docx
- `GET /judges/<id>/nomination` → «Представление к присвоению квалификационной категории» (.docx), кнопка «Скачать представление»
- CRUD для истории: `/judges/<id>/category-records`, `/judges/category-records/<id>/edit|delete` (и аналогично `training-records`, `competition-records`) — редактирование прямо на странице карточки судьи, произвольное число строк

`GET|POST /settings` (в `app.py`) — общая информация об организации.

## Синхронизация с сайтом RAFTING_CFO

Два независимых направления, оба через `.env` (`RAFTING_CFO_URL` / `RAFTING_CFO_API_KEY`, см. `.env.example`):

- **Семинары и заявки на семинар** — `sync_rafting_cfo.py` (см. `routes/seminars.py`): `POST /api/sync/events`, `POST /api/sync/seminar-applications`.
- **Судьи** — `sync_rafting_cfo_judges.py` (см. `routes/judges.py`): `POST /api/sync/referees`. Данные судьи попадают на сайт в общий список «Судьи» и в раздел «Спортивные судьи» на странице региональной федерации (сайт сопоставляет `territory` с наименованием субъекта РФ этой федерации — `Judge.region` уже хранит именно субъект РФ, отдельной настройки на этот счёт не нужно).

Отправка **не автоматическая** — по кнопке: одного судьи с его карточки («Отправить на сайт») либо всех разом со страницы списка («Отправить всех на сайт», нужно, чтобы на сайт гарантированно попали и включения, и исключения из активного списка). Исключение — `judges_delete`: удаление синхронизируется сразу, без кнопки, так как после удаления карточки нет страницы, откуда её нажать (для исключения из активного списка без удаления записи используется `is_active` — обычная отправка через кнопку).

## Генерация Word-документа (judge_docx_generator.py)

Документ **не строится с нуля** — вместо этого открывается образец `data/Учетная карточка судьи СС1К Серганова СА.docx` как шаблон, в нём находятся и заполняются нужные ячейки, а строки трёх повторяющихся таблиц (история категорий, подготовка, практика судейства) клонируются по количеству реальных записей судьи. Это сохраняет исходное форматирование, объединение ячеек и границы один в один.

Особенность вёрстки образца: у таблицы «подготовка» каждая запись занимает **3 физические строки** (первые 12 столбцов объединены по вертикали, последний столбец — дата внесения записи / пустая строка под подпись / ФИО ответственного — три отдельные незамёрженные ячейки). У таблицы «практика судейства» — **2 физические строки** на запись (аналогично: 4 общих столбца объединены, последний столбец — дата записи / ФИО ответственного). У таблицы истории категорий — 1 строка на запись, без объединений. `_replace_repeating_rows()` в `judge_docx_generator.py` реализует это клонирование по группам.

Перед сохранением обоих документов (карточки и представления) весь текст проходит `normalize_document()` из `judge_docx_generator.py`: «зачет» → «зачёт», между числом и «час…» — неразрывный пробел («2 часа», «16 часов» не рвутся). В представлении номера «КП № 1378-СМ» / «№ в ЕКП 29698» — неразрывные пробелы и дефис (`<w:noBreakHyphen/>`).

## Представление к присвоению категории (judge_nomination_generator.py)

Из образца `data/Представление СС1К Серганов СА.docx` берутся параметры страницы, строка-заголовок и блок подписей; строки с данными **собираются заново** (`_left_rows` / `_right_rows`), т.к. число семинаров и соревнований у каждого судьи своё. Таблица — одна, сетка 15 колонок (`GRID`): колонки 0–10 — сведения о судье и теоретическая подготовка, 11–14 — практика судейства; более короткая половина добивается пустыми строками.

Что откуда:
- присваиваемая категория — следующая после `current_category` (`NEXT_CATEGORY`); дата присвоения предыдущей — последняя запись «присвоена/восстановлена» действующей категории;
- семинары и соревнования — только отмеченные галочкой «В представление» (третий пункт ячейки «Действия» в обеих таблицах; `in_nomination`, `POST /judges/training-records/<id>/nomination` и `/competition-records/<id>/nomination`). Пока галочку не трогали (`None`), она стоит у записей после этой даты; по каждому семинару — строка «Теоретическая подготовка в объеме N академических часов» (часы из `participant_score`) и, если судья был лектором, «Проведение теоретических занятий…» (дата — `participant_date`); отдельным пунктом — сдача квалификационного зачёта последнего семинара (дата — `lecturer_date`);
- соревнование: наименование как есть, «должность, оценка» (баллы — внутри оценки);
- «Образование» — только уровень (`EDUCATION_LEVELS`: высшее, неоконченное высшее, среднее профессиональное…) без учебного заведения; не распознан — текст до запятой/скобки с пометкой;
- оценки семинаров выводятся без объёма часов («2 часа, зачет» → «Зачёт»); строка «Проведение теоретических занятий…» — дата лектора (`participant_date`, иначе дата семинара) и оценка лектора того же семинара;
- незаполненные данные в документ не подставляются — ячейка заливается **жёлтым** (`MARK_FILL`); так же помечаются неполные: нет «КП»/«ЕКП» в наименовании соревнования, нет «балл» в оценке, нет часов в оценке семинара, нет фото, нет руководителя организации;
- подпись — `Subject.organization_leader_*`, дата подписи — день выгрузки; фото — `Judge.photo_filename`.
